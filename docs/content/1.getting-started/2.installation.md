## Docker Compose

```bash
docker compose up -d --build
```

- Application : http://localhost:3900 (la configuration initiale crée le compte administrateur)
- API et documentation OpenAPI : http://localhost:8900/api/docs

## Développement sans Docker

```bash
# backend (PHP 8.4, PostgreSQL)
cd backend && composer install
php bin/console lexik:jwt:generate-keypair
php bin/console doctrine:migrations:migrate
php bin/console app:demo:seed            # avec DEMO_MODE=1 : lieux de démo
php -S 127.0.0.1:8900 -t public

# frontend
cd frontend && npm install && npm run dev -- --port 3900
```

## Intégrations

Les jetons des intégrations sont gardés chiffrés dans le **coffre des secrets** (Administration → Secrets), jamais dans le `.env` : générer la clé maîtresse avec `php bin/console rocket:secrets:generate-key` et la mettre dans `ROCKET_SECRETS_KEY` (`.env.local`). Une instance qui avait encore `NUKI_API_TOKEN` / `ROCKET_CLOUD_TOKEN` / `ROCKET_MAILER_TOKEN` les importe avec `php bin/console app:secrets:migrate-env` (idempotent), puis retire ces variables.

- `nuki.api_token` (coffre) : jeton de l'API web Nuki (droit `smartlock.auth` pour créer les codes), puis **Administration → Serrures → Synchroniser** et associe chaque serrure à son lieu. Les autres serrures et la domotique se configurent par lieu (**Administration → Plugins**, secrets dans le coffre, Administration → Secrets).
- `ROCKET_CLOUD_URL` + secret `rocket.cloud.token` : documents et photos de ménage dans Rocket Cloud.
- `ROCKET_MAILER_URL`, secret `rocket.mailer.token`, `ROCKET_MAILER_MAILBOX`, `ROCKET_MAILER_SENDER` : e-mails de ménage via Rocket Mailer (voir [Ménage](/usage/menage)).
- Le worker (`php bin/console messenger:consume async scheduler_default`) lance les tâches récurrentes (santé des services, e-mails quotidiens).

En mode suite (`ROCKET_AUTH_URL` + `ROCKET_AUTH_CLIENT_SECRET`), Rocket Cloud et Rocket Mailer sont appelés avec des jetons Rocket Auth ; les jetons statiques servent de repli.
